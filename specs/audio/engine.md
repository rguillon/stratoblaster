# Audio engine

> **Area:** Audio · **Prefix:** `AUD-ENGINE` · **Related:** [music.md](music.md), [sfx.md](sfx.md), [../ui/settings.md](../ui/settings.md), [../ui/pause-menu.md](../ui/pause-menu.md), [../01-engineering.md](../01-engineering.md), [../performance.md](../performance.md), [../dev/test-api.md](../dev/test-api.md)

The game's music is generated in the browser and its sound effects are recorded samples (CC0), both
played by a small, game-agnostic Web Audio engine: two buses into a limiter, a sequencer that
schedules notes ahead on the audio clock, a pool of sound effect voices with limits and priorities,
and cues read from the game's state. The
engine starts only after a user gesture, follows the pause and the page's visibility, and stays
silent without breaking anything when Web Audio is missing. What is played (the tracks, the sound
designs) is game data, in [music.md](music.md) and [sfx.md](sfx.md); the volume sliders are in
[ui/settings.md](../ui/settings.md).

## Requirements

### AUD-ENGINE-01 — Generated music, sampled sound effects · MUST

The music is generated by code with the Web Audio API (oscillators, looped noise, biquad filters,
gain envelopes, a convolver reverb). The sound effects are recorded samples under open licenses
compatible with the project's MIT license (CC0 only, [../01-engineering.md](../01-engineering.md)
ENG-121), each credited in `CREDITS.md` and the README. A sample is one short mono file in
`public/sfx/`, named after its sound (`gun-shot`, [sfx.md](sfx.md)), shipped twice: `<name>.ogg`
(Vorbis) and `<name>.mp3` for the browsers that cannot play Ogg (ENG-120). The game fetches the files
of every sound at once when it starts, so no screen waits for them, and decodes them with
`decodeAudioData` once the audio context exists (AUD-ENGINE-03).
A sample plays through an `AudioBufferSourceNode` into the sound effect bus (AUD-ENGINE-02), at the
sound's gain, looping only for the laser hum. No other audio file is shipped: the music has none.

A sound whose sample is not decoded yet, or failed to load or decode, is silent; nothing throws and
the game goes on (AUD-ENGINE-04).

**Acceptance criteria**
- Given the game played in the browser, then the only audio files fetched are
  `sfx/<sound>.ogg` (or `.mp3`), one per sound, all found, and no media element is created (e2e).
- Given the audio unlocked by a key press, then every sound's sample ends up decoded (e2e, the
  test API's `samples`).
- Given a production build, then every audio file is in `sfx/` and every `.ogg` has its `.mp3`
  (`make build` fails otherwise).
- Given a sample that is not ready, then its sound is silent and the voice pool still counts it
  (unit test).
- Given the sound files, then each is credited in `CREDITS.md` (review).

*Sources: GD-70, GD-71, P12-R05, D-097, D-261.*

### AUD-ENGINE-02 — Two buses and a limiter · MUST

The output has a **music** bus and a **sound effect** bus, each with its own volume, both into a
master limiter so the output never clips: a fast compressor whose threshold is `master_peak`
(−1 dBFS), ratio 20. A volume step `s` of the settings (0 to 10, [ui/settings.md](../ui/settings.md))
gives the bus gain (s / 10)² × the bus's mix level (`music_mix`, `sfx_mix`); 0 is silent. A volume
change ramps over 30 ms, so it does not click.

**Acceptance criteria**
- Given the music volume at 6, then the music bus gain is 0.36 × 0.8 (unit test).
- Given a volume of 0, then the bus is silent (unit test).

*Sources: P12-R05, P12-R10, D-097, D-099.*

### AUD-ENGINE-03 — Unlocked by the first gesture · MUST

Browsers only start audio after a user gesture, so the audio context is created (or resumed) on the
first key press, tap, click or gamepad button that the browser accepts as an activation, never
before. Nothing is heard before it, and no autoplay warning is ever shown.

**Acceptance criteria**
- Given the page just loaded with no input, then the audio context does not exist and the console
  shows no autoplay warning; after a key press, it runs (e2e).
- Given a gamepad button pressed, then the audio is unlocked (unit test).

*Sources: P12-R05, D-097.*

### AUD-ENGINE-04 — Silent without Web Audio · MUST

Without Web Audio, or if creating the context or its nodes throws, the game runs silently: every
screen works and no error is thrown. Audio promises that fail are not errors of the game, nor is a
sound file that fails to load or decode: that sound is silent (AUD-ENGINE-01).

**Acceptance criteria**
- Given a browser without `AudioContext`, then every screen works and nothing throws (unit test).
- Given a sound file that fails to load or to decode, then its sound is silent and nothing throws
  (unit test).

*Sources: P12-R05, D-097.*

### AUD-ENGINE-05 — Notes scheduled ahead · MUST

A sequencer hands out each track's notes ahead of time and the player schedules them on the audio
clock, `lookahead` (1.5 s) ahead, checked after every frame and on a timer every
`schedule_interval` (25 ms). So the music keeps time when frames are slow, and plays on through a
frozen frame shorter than the lookahead (a loading step, the first frames of a level). Fades,
cross-fades, pausing and volume changes still apply to the notes already scheduled.

**Acceptance criteria**
- Given a frozen frame of 1 s while a track plays, then the music has no gap (unit test).
- Given a track fading out, then its notes scheduled ahead fade with it and stop when the fade ends
  (unit test).

*Sources: P12-R05, D-097, D-120.*

### AUD-ENGINE-06 — Echo and reverb · MUST

Each playing track has its own mixer, which gives every instrument sends to a tempo-synced echo
(`echo_beats` 0.75 of a beat, feedback 0.35) and to one shared reverb on the music bus (a
generated, decaying noise impulse of 2.2 s, the same on every run, never from `Math.random`). The
sends fade with their track. Which instruments send how much is game data.

**Acceptance criteria**
- Given a track whose instruments send to the echo and the reverb, then their sound reaches the
  music bus through both, and the music volume applies to the reverb's tail too (unit test).

*Sources: D-099.*

### AUD-ENGINE-07 — Sound effect voices · MUST

So busy screens stay pleasant:
- at most `sfx_voices_max` (16) sound effects play at once; when they are all taken, a new sound
  replaces the oldest playing sound of lower or equal priority, or is dropped if there is none;
- the same sound started again within `sfx_retrigger_min` (30 ms) is not played twice: the one
  playing is made ×1.25 louder instead (at most ×1.56);
- a looping sound (the laser hum) plays once until it is stopped.

The limits count in the app's own time, so they behave the same in every run.

**Acceptance criteria**
- Given 40 explosions in one frame, then at most 16 sounds play (unit test).
- Given the same hit sound asked twice 10 ms apart, then it plays once (unit test).
- Given a player sound asked while every voice plays an enemy shot, then it plays (unit test).

*Sources: P12-R10, D-097.*

### AUD-ENGINE-08 — Panning by position · MUST

Sound effects that follow a position on the playfield (the player's and the enemies' shots, hits,
explosions; the sound designs say which, [sfx.md](sfx.md)) are panned left or right with their x: −`sfx_pan_max` (−0.6) at the left edge, 0 in the middle,
+0.6 at the right edge.

**Acceptance criteria**
- Given an explosion at the left edge, then its pan is −0.6; in the middle, 0 (unit test).

*Sources: P12-R09, D-097.*

### AUD-ENGINE-09 — Cues from the game's state · MUST

The audio only reads the game's state, it never changes it (ENG-11). After each simulation step,
the level's state is compared with the step before and turned into cues (a volley fired, a beam
started, an enemy shot, a laser warning or beam, a hit or a blocked hit, a hit on the player, a
small or large explosion, a boss part or a boss destroyed, a life lost or gained, a bomb, a bonus
picked up, a weapon switched or levelled up), at most one cue of each kind per step. The menus give
their own cues (move, confirm, back, pause, resume, slider). The game maps each cue to a sound
design ([sfx.md](sfx.md)); a cue without one is silent.

**Acceptance criteria**
- Given each event, then its cue is given on the step it happens, once (unit test with one case per
  event).
- Given ten enemy bullets fired in one step, then one `enemy-bullet` cue is given (unit test).

*Sources: P12-R09, D-097.*

### AUD-ENGINE-10 — Following the pause · MUST

When the game pauses, the music pauses at its position (the notes sounding fade out in
`pause_fade`, 50 ms) and every playing sound effect stops. Resuming goes on from the same position.
The menu sounds of the pause menu and the settings screen still play while paused.

**Acceptance criteria**
- Given a level track 30 s in, when the game is paused for 10 s and resumed, then the track goes on
  from about 30 s, not 40 s (unit test on the position).
- Given the pause menu, when the selection moves, then the menu move sound plays (e2e).

*Sources: P12-R11, D-095.*

### AUD-ENGINE-11 — Following the page · MUST

When the page is hidden, all audio is silenced (the audio context is suspended); it resumes when
the page is visible again. (The level also pauses, [ui/pause-menu.md](../ui/pause-menu.md).)

**Acceptance criteria**
- Given the page hidden, then the audio context is suspended; visible again, it runs (e2e with a
  faked `visibilitychange`).

*Sources: P12-R11, D-095, D-097.*

### AUD-ENGINE-12 — No cost to the frame rate · MUST

Generating and playing the audio does not lower the frame rate below the 60 fps target
([performance.md](../performance.md)), even in the busiest level with music and sound effects on.

**Acceptance criteria**
- Given the busiest World 4 level with music and effects on, then it stays at 60 fps on the
  reference machine (manual check).

*Sources: P12-R05.*

### AUD-ENGINE-13 — Engine and game apart · SHOULD

The audio engine (`src/audio/`: context and unlock, buses and limiter, sequencer, synth voices,
sample bank, voice pool, track mixer, music and sound effect players, cue extraction) knows no game: the
tracks, instruments, sound designs (which sample, gain, priority), mix levels and the cue → sound
map are the game's data
(`src/game/view/audio/`). The pure parts (sequencer, voice pool, cues, composers) are unit tested
without real audio, with a fake audio context for the rest.

*Sources: P12-R05, D-097.*

## Tunable values

| Name | Value | Notes |
|------|-------|-------|
| volume steps | 0 … 10, gain (step / 10)² | `src/config/audio.py` `AUDIO_CONFIG.volume_steps`; defaults are in [ui/settings.md](../ui/settings.md) |
| music_mix / sfx_mix | 0.8 / 1 | `src/game/view/audio/game_audio.py` `MIX` (D-099; were 0.5 / 0.8) |
| master_peak | −1 dBFS | `AUDIO_CONFIG.master_peak_db` |
| limiter | knee 0, ratio 20, attack 3 ms, release 0.25 s | `AUDIO_CONFIG.limiter` |
| lookahead | 1.5 s | `AUDIO_CONFIG.lookahead_seconds` (D-120; was 100 ms) |
| schedule_interval | 25 ms | `AUDIO_CONFIG.schedule_interval_seconds` |
| pause_fade | 50 ms | `AUDIO_CONFIG.pause_fade_seconds` |
| sfx_voices_max | 16 | `AUDIO_CONFIG.max_voices` |
| sfx_retrigger_min / boost | 30 ms / ×1.25 (at most ×1.56) | `AUDIO_CONFIG.retrigger_seconds`, `.retrigger_boost` |
| sfx_pan_max | 0.6 | `AUDIO_CONFIG.pan_max` |
| echo / reverb | 0.75 beat, feedback 0.35 / 2.2 s | `src/game/view/audio/game_audio.py` `EFFECTS` |
| gesture events | `keydown`, `pointerdown`, `pointerup`, `touchend`, any gamepad button | `src/app/page_audio.py` `GESTURE_EVENTS` |

## Notes

- Web Audio has no true-peak limiter: a very loud pile-up can overshoot −1 dBFS by a fraction of a
  dB for a few milliseconds.
- If the first key pressed is Escape (not an activation for browsers), the audio starts on the
  next key, tap or click.
- The 60 fps check with sound on (AUD-ENGINE-12) is a manual check that was never recorded (phase 12
  known limitation).
- A first fix scheduled the music 1.5 s ahead only before each loading step; it was not enough and
  was replaced by the 1.5 s lookahead (the two D-120 entries).
